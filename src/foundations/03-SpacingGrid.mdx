## Safe-area — by archetype

It's not a single value: the harness extracted a generic average (`--slide-safe-area`, 160), but
layout.md refined it by screen type — dense slides use less margin than covers/hero.

<ScaleBar name="--slide-safe-area" label="generic (harness)" max={260} />
<ScaleBar name="--slide-safe-area-hero" label="hero / Divider" max={260} />

Dense slides (Who is Vinta, Client-case) use a **64px** margin — narrower than the two
tokens above; it doesn't have its own token yet (it stays as a composition value in the pattern, not a
global token) because no dense archetype measured exactly 160.

## Do / Don't

**Do**
- Use `space-2` (14) as the default gap; go up to `space-3`/`space-4` only when the layout calls for
  more breathing room (e.g. section separation).
- Use `--slide-safe-area-hero` on covers/Divider; ~64 margin on dense content slides.

**Don't**
- Invent a gap value outside the scale without recording why (see Divider/MetricGrid, which
  compose a `calc()` of two tokens instead of using a loose number when the real gap falls between
  two steps).
